# Hezil HES — Giriş (Login) & Oturum Özelliği Spec

**Status:** Draft — awaiting implementation approval
**Date:** 2026-08-11
**Related files:** `pano_sunucu.py`, `dashboard.py`, `hezil_dashboard.html`, `requirements.txt`, (new) `.env`, `.env.example`, `.gitignore`, `giris_cikis.log`

---

## 1. Overview

Add a simple, design-consistent **login gate** to the Hezil HES dashboard server:

- Credentials live in a `.env` file (multiple users).
- A correct login reveals the dashboard; wrong credentials are rejected.
- After **1 hour of idle** (no page interaction), the session expires and the user is returned to the login screen ("oturum süresi doldu").
- The dashboard header shows the **logged-in username and a "Çıkış" (logout) button**.
- Every login/logout event (manual **or** automatic) is appended to a **log file**.

The feature is intentionally **lightweight** — the goal is access control & audit for a LAN/internet-exposed instance of `pano_sunucu.py`, not a security fortress.

---

## 2. Decisions (from user interview)

| # | Topic | Decision |
|---|-------|----------|
| 1 | User model | **Multiple users** defined in `.env` |
| 2 | Standalone (`file://`) mode | **Keep bypass** — double-clicking the HTML still shows the full dashboard with no login (auth is only enforced when served by `pano_sunucu.py`) |
| 3 | Session persistence | **Browser session only** — cookie without `Max-Age`/`Expires`; closing the browser logs out |
| 4 | Idle definition | **Page interaction** (mouse move/down, keydown, click, scroll, touch) resets the 1-hour timer |
| 5 | Expiry UX | **Immediate redirect** to the login overlay with an "oturum süresi doldu" notice (no countdown warning) |
| 6 | Log contents | Successful logins, failed attempts, logout reason (manual vs idle) + **client IP**, **plain-text** lines, Turkish labels |
| 7 | Password storage | **Plain text** in `.env` (`.env` is not committed to git) |
| 8 | What is gated | **Dashboard + API only** — other static files (`.py`, `.xlsx`, `.csv`) remain publicly served |
| 9 | `.env` parsing | **`python-dotenv`** added to `requirements.txt` |
| 10 | Configurability | Idle timeout (`OTURUM_SURE_S`) and log file path (`LOG_DOSYASI`) configurable via `.env`, with defaults |
| 11 | Login UI location | **Inline overlay** inside `hezil_dashboard.html` (same file → pixel-identical styling); standalone mode skips it |
| 12 | Concurrent sessions | **Allowed** — each login creates an independent session; the same user may be logged in from several browsers |
| 13 | Server restart | **In-memory sessions only** — a restart logs everyone out (they simply log in again) |

## 4. Requirements

### 4.1 Functional
- F1. Login screen matching the dashboard look (same CSS variables, dark/light theme, fonts, header style).
- F2. Credentials read from `.env`; **multiple users** supported.
- F3. Valid credentials → dashboard visible. Invalid → error message, stays on login.
- F4. 1-hour idle timeout → automatic logout → login screen with "oturum süresi doldu" notice.
- F5. Header shows `👤 <kullanıcı adı>` + "Çıkış" button (only when a server session exists).
- F6. Log file records every login/logout (manual + automatic), with failed attempts, username, IP, and reason. Thread-safe appends.

### 4.2 Non-functional
- NF1. Zero disruption to standalone (`file://`) usage — full bypass (decision #2).
- NF2. Zero new runtime dependency beyond `python-dotenv`.
- NF3. All UI strings Turkish (project convention).
- NF4. API endpoints gated server-side (real 401s), not just hidden client-side.
- NF5. Session tokens cryptographically random (`secrets`).
- NF6. All existing dashboard features keep working after login.

## 5. Detailed design

### 5.1 `.env` format

Parsed with `python-dotenv` via **`dotenv_values(os.path.join(KD, ".env"))`** — returns a plain dict without touching `os.environ`, so credentials never leak into the process environment (visible to any child process) and OS env vars can't silently override the file. The `.env` file is the single source of truth for credentials. (Latest 1.1.x line **officially supports Python 3.14** — PyPI classifier verified 2026-08-11; pure-Python, no compiled deps.)

```dotenv
# Hezil HES — kullanıcılar ve oturum ayarları
KULLANICI_1_ADI=ismet
KULLANICI_1_SIFRE=sifre123
KULLANICI_2_ADI=ayse
KULLANICI_2_SIFRE=parola456

# Saniye cinsinden hareketsizlik süresi (varsayılan: 3600 = 1 saat)
OTURUM_SURE_S=3600

# Giriş/çıkış kayıt dosyası (varsayılan: giris_cikis.log)
LOG_DOSYASI=giris_cikis.log
```

Rules:
- Users: **scan all keys matching the `KULLANICI_<N>_ADI` / `KULLANICI_<N>_SIFRE` pattern** (don't stop at the first gap — e.g. `KULLANICI_3_` must still be found when `KULLANICI_2_` is missing). Username and password comparison is **exact and case-sensitive** (simplest; documented). Duplicate usernames → last one wins with a console warning.
- `OTURUM_SURE_S` default **3600**; **validated: missing / non-numeric / < 10 → warning + default 3600** (≥ 10 accepted as-is). This blocks foot-gun values like `0` (instant expiry → infinite logout loop) while still allowing fast expiry testing (§9 uses `OTURUM_SURE_S=10`).
- `LOG_DOSYASI` default **`giris_cikis.log`** (relative to `KD`); if its parent directory doesn't exist, create it (`os.makedirs(..., exist_ok=True)`); if the file can't be opened, fall back to `giris_cikis.log` with a warning.
- **Fail fast:** if `.env` is missing or contains **no users**, `main()` prints a clear Turkish error (including the expected path) and exits non-zero. Auth is the gate; the server must not run without it.
- Parse defensively: **usernames are trimmed; passwords are used verbatim** (leading/trailing spaces in a password are intentional — `dotenv_values` handles quoting). Pairs with an **empty username or empty password are skipped** with a one-line console warning.
- `.env` is **never committed** (see §5.8). A committed **`.env.example`** (this exact template) documents the format.

### 5.2 Session model (in-memory)

```python
_oturumlar = {}        # token -> {"kullanici": str, "son_aktivite": float, "olusturma": float, "ip": str}
_oturum_kilit = threading.Lock()   # separate from _kilit (DP lock) — sessions must never block DP work
```

- Token: `secrets.token_urlsafe(32)`.
- Cookie: name **`hezil_oturum`**, value = token. Flags: `HttpOnly`, `SameSite=Lax`, `Path=/`, **no** `Max-Age`/`Expires` (browser-session cookie, decision #3).
- `son_aktivite` (epoch seconds) is refreshed on:
  - successful `/api/giris`,
  - heartbeat `/api/nabiz`,
  - **any other authenticated request** — but **only after the expiry check passes** (ordering: check `now - son_aktivite > OTURUM_SURE_S` first → if expired, terminate + 401; else refresh).
- `GET /api/oturum` is deliberately **passive** — it must *not* refresh `son_aktivite` (so it can't be used to keep sessions alive).
- Multiple sessions per user allowed (decision #12). Logout invalidates only the caller's token.
- **Lock ordering (deadlock avoidance):** `_oturum_sonlandir` / `_kayit_ekle` may need both locks — **always acquire `_oturum_kilit` first, then `_log_kilit`** (never the reverse), so request threads and the janitor can't deadlock.

### 5.3 HTTP endpoints (new)

| Endpoint | Auth | Purpose |
|---|---|---|
| `POST /api/giris` | public | Body `kullanici` + `sifre`. Success → create session, `Set-Cookie`, log `GİRİŞ`, return `{"ok":true,"kullanici":"…"}`. Failure → log `HATALI GİRİŞ`, **sleep ~0.5 s** (slow down brute force), 401 `{"hata":"kullanıcı adı veya parola hatalı"}`. Missing fields → 400. |
| `POST /api/cikis` | **public** | Manual logout — **intentionally public** so it can be idempotent (the table row and gating rule must not contradict). Reads the cookie if present, invalidates that session (log `ÇIKIŞ` `neden=elle (çıkış düğmesi)` **only if a session was actually terminated**), clears the cookie (`Max-Age=0`), always returns 200 `{"ok":true}`. CSRF-safe: with `SameSite=Lax` a cross-site POST cannot carry the cookie, so an off-site form cannot log anyone out. |
| `POST /api/nabiz` | session | Heartbeat; refreshes `son_aktivite`. Returns `{"ok":true,"kullanici":"…"}`. If expired → 401 (see §5.4). |
| `GET /api/oturum` | passive | Session probe. Valid → 200 `{"oturum":true,"kullanici":"…"}`; none/invalid → 401 `{"oturum":false}`. Used at page load + to distinguish standalone vs served mode. No activity refresh. |
| `GET /api/durum` | **public** | Left public deliberately — it is the pre-auth health check (`curl http://IP:8765/api/durum` per DEPLOYMENT.md) and only leaks port + cache count. |

Gating rule in `do_GET`/`do_POST`: **every `/api/*` path requires a valid session, except the four session/health endpoints — `/api/giris` (login), `/api/cikis` (idempotent logout, always 200), `/api/durum` (public health), `/api/oturum` (session probe, checks the cookie itself: valid → 200, else → 401 with the specific `{"oturum":false}` shape)**. All other `/api/*` paths (`/api/nabiz`, `/api/isletme`, `/api/imalatci`, `/api/enkesit`) without a valid session get 401 JSON `{"hata":"oturum geçersiz — giriş yapın"}`; `WWW-Authenticate` is not needed (page-based auth). Static files remain public (decision #8). HTML pages (`/`, `*.html`) remain publicly servable — the client-side overlay enforces the login UX (see §5.5 and the trade-off in §7).

Robustness details:
- `POST /api/giris` reads the body with a **4 KB cap** (larger → 413 `{"hata":"istek çok büyük"}`) — a malicious client can't exhaust memory.
- Unknown `/api/*` paths (e.g. a bare `GET /api/giris`) fall through to default static serving → 404 (acceptable; no special handling).
- Every JSON response (including 401s, login, logout) already goes through `_json`, which sets `Cache-Control: no-store` (pano_sunucu.py L120) — no auth response can be cached by the browser.

Helper on `SimpleHTTPRequestHandler`: `_cerez_al()` (read `Cookie` header), `_cerez_kur(token, sil=False)` (emit `Set-Cookie`). A `do_POST` method is added (currently only `do_GET` exists) with `urllib.parse.parse_qs` on the request body.

### 5.4 Idle timeout (1 hour)

Two cooperating mechanisms:

1. **Client (primary signal — "page interaction", decision #4):**
   - Listeners on `mousemove`, `mousedown`, `keydown`, `click`, `scroll`, `touchstart`.
   - **The heartbeat is armed ONLY while the client believes it is authenticated** (JS flag `OTURUM_AKTIF`, set after the boot session check returns 200 or after a successful `/api/giris`; cleared by `oturumDoldu()` and by manual logout). Without this, typing on the login form (keydown) or moving the mouse would fire heartbeats → spurious 401s → the "süresi doldu" notice could appear *while the user is logging in*.
   - When armed and activity occurs **and** ≥ 60 s have passed since the last heartbeat, send `POST /api/nabiz` (throttled/debounced; `mousemove` alone must not flood — throttle to one check per ~2 s, heartbeat at most once per 60 s).
2. **Server (enforcement):**
   - On every authenticated request: if `time.time() - son_aktivite > OTURUM_SURE_S` → invalidate session, log `ÇIKIŞ` `neden=hareketsizlik (süre aşımı)` once (via shared `_oturum_sonlandir(token, neden)`), return 401.
   - **Janitor thread** (daemon, started in `main()`): every 60 s sweeps expired sessions, calling the same `_oturum_sonlandir` so automatic logouts are logged **even if the user never makes another request**.

Client handling of any 401 from `/api/*`: immediately show the login overlay with the notice **"Oturum süresi doldu — yeniden giriş yapın."** (immediate redirect, decision #5).

### 5.5 Dashboard HTML changes (`dashboard.py` → regenerate `hezil_dashboard.html`)

**Header (right side):** user chip with username + logout button.

⚠️ **Placement constraint (verified):** `kurSekmeler()` **rewrites `#sekmeler.innerHTML`** on every scenario toggle (dashboard.py L592) — the chip must therefore be a **sibling of `#sekmeler`, never a child**, or it would be wiped. The header currently is a plain block (`header{...position:sticky}` — **not** flex), so it must be restructured minimally:

```html
<header>
  <div style="flex:1 1 auto;min-width:0">
    <h1>Hezil Barajı ve HES — Alternatif Analiz Panosu</h1>
    <div class="altbaslik" id="ustbilgi"></div>
  </div>
  <div id="kullaniciKutu" style="display:none;align-items:center;gap:8px">
    <span id="kullaniciAdi"></span>
    <button id="cikisDugmesi" class="kopyala">Çıkış</button>
  </div>
  <div class="sekmeler" id="sekmeler" style="flex:1 1 100%"></div>
</header>
```

with `header{display:flex;flex-wrap:wrap;align-items:center;column-gap:14px}`. The title block (`flex:1 1 auto`) pushes the chip to the right edge; `.sekmeler` gets `flex:1 1 100%` so the tab row always wraps onto its own full-width line — the visual layout is otherwise unchanged. The chip is hidden by default (`display:none`) and shown only when a server session exists; standalone mode keeps it hidden (no user to show).

**Login overlay:** a fixed full-screen `<div id="girisKatmani">` (background = `var(--bg)`; centered card using the same panel/border/radius variables as `.kutu`; dark/light aware automatically). It must be **visible by default in the markup** (NOT `display:none`) because the dashboard's init is synchronous at script end (`kurSekmeler(); kurSecimler(); ciz();` — dashboard.py L1522, not a `load` event): the overlay sits on top and prevents a dashboard flash, then JS hides it on success. Needs `z-index:100` — above the sticky header (z-index 20) and `#ipucu` (z-index 50). Contents:
- Title "Hezil HES — Alternatif Analiz Panosu" (consistent with header `h1`).
- Subtitle "Devam etmek için giriş yapın".
- Inputs: "Kullanıcı adı" + "Parola" (type=password; Enter submits).
- Error line (red, `#cf222e`-ish): wrong credentials, or the "oturum süresi doldu" notice — both rendered in the same element with distinct text.
- Submit button styled like `.dugme` ("Giriş").

**Boot sequence (JS):** the synchronous init `kurSekmeler(); kurSecimler(); ciz();` (L1522) stays exactly as-is — the overlay (visible by default) simply covers the rendered dashboard. Immediately after init, an async session check runs:

```
after init:
  GET /api/oturum
    → network error  ⇒ standalone mode: hide overlay, run dashboard as today (bypass)
    → 200 oturum:true ⇒ hide overlay, fill #kullaniciAdi, show #kullaniciKutu
    → 401             ⇒ stay on overlay (login screen)
```

- **Server-presence vs session-state are separate:** keep `sunucuYokla()` (dashboard.py L1057 — fetches `api/durum`, which stays public) exactly as-is for server presence; add a new `oturumYokla()` for session state (`/api/oturum`). `sunucuYokla()`'s cached `SUNUCU` flag must not be confused with auth state.
- Login form submit → `POST /api/giris` → ok: hide overlay + show user chip; error: show message.
- "Çıkış" button → `POST /api/cikis` → hide chip, show overlay (user is logged out again).
- **Shared 401 handler `oturumDoldu()`** — hook the exact sites where fetches occur, noting their different current error handling:
  - `dGetir()` (L1071): already checks `!c.ok` → throws `"sunucu hatası " + c.status` (L1072); on `c.status === 401` call `oturumDoldu()` **instead of throwing**.
  - imalatçı paketi (L1437-1438) and en kesit (L1483-1484): these two have **no `!c.ok` check at all** — they parse `c.json()` unconditionally and rely on `j.hata`. On a 401 they would render "Paket üretilemedi: oturum geçersiz…". Insert an explicit `if (c.status === 401) return oturumDoldu();` **before** `c.json()` in both.
  - `oturumDoldu()` must fire *before any throw*: `detayCiz()` prefetches the other operation mode via `dGetir(d, oteki).catch(() => {})` (L1160) which swallows errors — throwing alone would silently skip the overlay in that path.
  - `oturumDoldu()`: clears `OTURUM_AKTIF`, hides `#kullaniciKutu`, shows the overlay, and stops further rendering. The "oturum süresi doldu" notice is shown **only if the overlay was not already visible** (if the user is already on the login screen — e.g. a stray heartbeat 401 — it stays a plain login form, no expiry message).
  - After `oturumDoldu()`, `dGetir()` returns `null` (same as the standalone path) so the "start the server" box is not rendered behind the overlay.
  - Username is always written via **`textContent`** (never `innerHTML`) — it originates from `.env` and must not be injectable.
- Heartbeat listeners per §5.4 (armed only when `OTURUM_AKTIF`).
- **Accepted UX note:** on a refresh with a valid session, the overlay is visible for ~100–300 ms until `oturumYokla()` returns 200 — a brief login-screen flash is expected and acceptable.

### 5.6 Log file

- Path: `KD / LOG_DOSYASI` (default `giris_cikis.log`), appended in **UTF-8**, one line per event.
- Writes protected by a small lock (`_log_kilit`) — `ThreadingHTTPServer` is multi-threaded.
- Log events: **GİRİŞ** (success), **HATALI GİRİŞ** (failed attempt), **ÇIKIŞ** (manual or auto, with `neden`).
- Format (local time `YYYY-MM-DD HH:MM:SS`):

```
2026-08-11 14:32:01 | GİRİŞ         | kullanıcı=ismet | ip=192.168.1.20
2026-08-11 14:32:05 | HATALI GİRİŞ  | kullanıcı=admin | ip=10.0.0.5
2026-08-11 15:32:01 | ÇIKIŞ         | kullanıcı=ismet | ip=192.168.1.20 | neden=hareketsizlik (süre aşımı)
2026-08-11 15:35:12 | ÇIKIŞ         | kullanıcı=ayse  | ip=192.168.1.30 | neden=elle (çıkış düğmesi)
```

- A failed attempt logs `HATALI GİRİŞ`; a later successful login with the same credentials logs `GİRİŞ` — each event is its own line.
- Auto-logout is logged exactly once, at the moment the session is invalidated (lazy check on next request **or** janitor sweep — whichever happens first), via the shared `_oturum_sonlandir(token, neden="hareketsizlik (süre aşımı)")` helper. Manual logout logs `neden=elle (çıkış düğmesi)`.

**Implementation note (added post-review): real client IP.** The log records the TCP peer
address — testing from the same machine therefore shows `127.0.0.1` (normal). Behind a reverse
proxy (nginx/Caddy → `127.0.0.1:8765`), every peer is the proxy, so the real client is read from
`X-Forwarded-For` — but only when the connection comes from an address listed in `GUVENILIR_PROXY`
in `.env` (empty = XFF ignored, spoof-proof). Applied in `_istemci_ip()`; used at login (the
session stores the same IP for its `ÇIKIŞ` line).

## 6. Edge cases

| Case | Behavior |
|---|---|
| `.env` missing / empty | Server refuses to start, clear Turkish error printed. |
| Empty username or password submitted | 400, generic error text. |
| Wrong password | 401, `HATALI GİRİŞ` logged, ~0.5 s delay. |
| Same user, two browsers | Both sessions stay valid (decision #12). |
| Idle > 1 h, user returns | Next request → 401 → overlay "süresi doldu"; janitor logs it even if they never return. |
| Manual logout | Session deleted + cookie cleared; header chip hidden; overlay shown. |
| Server restarted | All sessions gone; next page load shows login overlay. |
| `file://` standalone | `api/oturum` fetch fails → bypass; full dashboard; no user chip, no logout button. |
| Server not running (`http://` to dead port) | Same as standalone: fetch fails → dashboard with existing "sunucuyu başlatın" notices. |
| Two tabs open | Shared cookie; either tab's heartbeat keeps the session alive; expiry in one tab → overlay there (other tab follows on its next interaction/request). |
| API call in flight when session expires | Returns 401 → shared handler → overlay + notice. |
| User already logged in, hits login page | Page load check shows dashboard immediately (no re-login). |
| HTTP + `SameSite=Lax` | Cookie sent on same-site requests; fine for direct IP/port access. Also makes the public `/api/cikis` CSRF-safe (cross-site POST can't send the cookie). |
| `/api/cikis` without a session | 200 idempotent; cookie cleared if present; no `ÇIKIŞ` line logged (no session was terminated). |
| `OTURUM_SURE_S=0` / garbage / < 10 | Invalid → warning + default 3600; server never enters instant-expiry mode. |
| Huge login POST body | 413; body read capped at 4 KB. |
| Typing on the login form | No heartbeat fires (`OTURUM_AKTIF` false) → no spurious "süresi doldu" notice. |
| User enumerated with a gap (`KULLANICI_1_` + `KULLANICI_3_`) | Pattern scan finds both; no stop-at-first-gap. |

## 7. Security posture & known trade-off

By design (user decisions #2, #8, #11):
- **Server-enforced protection:** all `/api/*` except the four public session endpoints (`giris`, `cikis`, `durum`, `oturum`) return real 401s — live operation studies, manufacturer packages, and cross-section generation are inaccessible without a valid session.
- **Client-side protection only:** the dashboard HTML (with embedded scan data) is served to anyone and the login overlay is JS — trivially bypassable by opening the file directly or reading the source. This is the *accepted* consequence of "inline overlay + standalone bypass + dashboard-only gating". If stricter gating is ever needed, the upgrade path is: serve `/` as a minimal login page (no embedded data) until authenticated, and/or gate all static files — both are documented here but **not implemented**.
- Static repo files (`.py`, `.xlsx`, `.csv`) stay public (decision #8).
- **Deployment caveat (add to DEPLOYMENT.md):** auth exists only when the page is served by `pano_sunucu.py`. Hosting the same HTML on any other static host (DEPLOYMENT.md Path A: nginx, GitHub Pages, `python -m http.server`) — or opening it via `file://` — bypasses login entirely. Consistent with decision #2, but anyone publishing the dashboard elsewhere should know the gate does not travel with the file.
